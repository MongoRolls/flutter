# 智能手表提醒支持（plan）

> 文档类型：产品 + 工程规划。范围：**Flutter 客户端**（`flutter/`）；不含 `web/`。  
> 目标：在**不强制开发独立手表 App** 的前提下，让用户在常见智能手表上**稳定收到**与手机一致的喝水/自定义/关怀类本地提醒。

---

## 1. 背景与原则

- 当前提醒链路：**手机端** `flutter_local_notifications` 调度本地通知（`NotificationService`：周期喝水、自定义提醒、关怀通知等）。
- **智能手表**（Apple Watch、Wear OS、华为/小米等）在绝大多数场景下**不单独跑 Flutter App**，而是通过 **手机通知镜像** 到表端。
- 本 plan 的「支持」指：**工程上保证通知可被系统正确转发** + **用户侧有可理解的设置指引**；**不**默认承诺表盘复杂功能、独立记饮水等原生表端能力（另立项）。

---

## 2. 目标与非目标

### 2.1 目标（应达成）

| 编号 | 目标 | 说明 |
|------|------|------|
| G1 | **镜像可达** | 用户在手表与手机正常配对、系统允许同步通知时，能收到与手机同源的提醒（标题/正文以系统展示为准）。 |
| G2 | **渠道与优先级合理** | Android 上喝水/自定义/关怀等使用**高重要性**通知渠道，降低被系统静默、手表不弹的概率（在合规前提下）。 |
| G3 | **可验证** | 团队有**复现清单**（至少：Android+Wear、iPhone+Apple Watch；可选一条国产表+安卓机）。 |
| G4 | **用户说明** | 设置或帮助文案中说明「依赖手机通知同步至手表」，并指向系统/穿戴 App 中的通知开关（避免误认为需单独安装表端 App）。 |

### 2.2 非目标（本 plan 不覆盖）

- 开发 **watchOS / Wear OS 独立应用**、表盘 Complication、脱离手机的独立提醒。
- 替代厂商推送（FCM/APNs）实现「无手机也能实时推」——若未来需要，另起「远程推送」专项。

---

## 3. 技术要点（现有代码基础上的增量）

### 3.1 无需改代码即可成立的部分

- 本地通知一旦在**手机**上按预期触发，**是否出现在手表**主要由 **OS + 穿戴配对设置** 决定，应用侧无法 100% 控制。
- 因此「支持手表」的**第一优先级**是：**手机端通知本身可靠**（权限、省电限制、精确闹钟等已有讨论与实现）。

### 3.2 建议的工程核对项

| 项 | 平台 | 建议动作 |
|----|------|----------|
| 通知渠道重要性 | Android | 确认 `AndroidNotificationDetails` 中 `importance` / `priority` 与业务一致；喝水、自定义、关怀等若分 channel，均避免被设为 `low`/`min` 导致手表侧被折叠或不同步。 |
| 类别与展示 | iOS | 已有 `DarwinNotificationDetails`；若后续需「静音预览」等差异，再考虑 `categoryIdentifier`（非本 plan 必做）。 |
| 通知 ID 冲突 | 全端 | 保持与现有文档一致：不同业务线**固定 ID 区间**，避免取消/覆盖导致用户误以为「手表没提醒」。 |
| 测试通知 | 全端 | 设置里若有「测试通知」，在文档中说明：**手表需开启从手机同步通知**后才可见表端效果。 |

### 3.3 可选增强（按优先级排期）

1. **设置页短文案 + 外链/帮助**：「使用智能手表时，请在系统或穿戴 App 中允许本应用通知同步到手表。」
2. **FAQ / 文档索引**：在 `.cursor/project/文档索引.md`（若维护）中增加一条链到本文或产品帮助页。
3. **Android 13+**：确认 `POST_NOTIFICATIONS` 与渠道授权流程完整（项目若已处理则仅回归）。

## 4. 验收标准（建议）

| 场景 | 验收 |
|------|------|
| Android 手机 + Wear OS 手表 | 手机收到「渴了么」定时提醒时，手表在默认通知设置下能收到同步（允许 1 次系统设置引导）。 |
| iPhone + Apple Watch | 同上，以 iOS 通知与 Watch 镜像设置为准。 |
| 文档 | 产品/设置内可见简短说明，与「依赖手机同步」表述一致，无「必须安装手表版」误导。 |

---

## 5. 风险与说明

- **厂商差异**：华为/小米/OPPO 等穿戴客户端对「手机通知同步到表」的策略不一，**无法**在应用内统一开关，只能依赖用户设置与帮助文案。
- **省电与后台**：与现有本地提醒相同，极端省电模式下可能出现延迟或不同步，需在支持文档中诚实说明。

3. QA：按 §4 准备两台组合做手工回归，结果记入发布说明或内部 wiki。  
4. （可选）更新 `文档索引.md` 指向本 `plan.md`。
