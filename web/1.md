问题分层
层 1：setTheme 到底有没有执行？
你说「有 UI 响应」——这可能只是 buttonVariants 里的 :active 按压动画（translate-y-px），并不代表 onClick 真正触发了 setTheme。上一轮已经把所有 console.log 都删除了，所以控制台没输出是预期的。

层 2：<html> 上有没有出现 dark 类？
next-themes 会通过 document.documentElement.classList.add("dark") 来切换主题。如果这一步没发生，页面自然不变。

层 3：CSS 变量有没有生效？
globals.css 里 :root 定义了浅色变量、.dark 定义了深色变量（背景从 #F5F8FF → #0A0E1A）。如果 .dark 类在但颜色没变，说明 CSS 解析出了问题。

步骤 1：确认按钮在不在
document.querySelector('[data-kelem-theme-toggle]')

import { buttonVariants } from "@/components/ui/button";
import { cn } from "@/lib/utils";
/**
 * 原生 <button> + next-themes；浅色为 html.light，深色为 html.dark（见 globals.css 变量）。
 */
export function ThemeToggle() {
  const [mounted, setMounted] = React.useState(false);
  const ref = React.useRef<HTMLButtonElement>(null);
  const isDark = resolvedTheme === "dark";
  /**
   * 用原生 DOM 事件保底：pnpm + Next 16 App Router 环境下
   * React 合成事件有时因 hydration 问题不触发。
   */
  React.useEffect(() => {
    const el = ref.current;
    if (!el) return;
    const handler = () => {
      const html = document.documentElement;
      const hasDark = html.classList.contains("dark");
      const next = hasDark ? "light" : "dark";
      html.classList.remove("light", "dark");
      html.classList.add(next);
      html.style.colorScheme = next;
      try {
        localStorage.setItem("kelem-theme", next);
      } catch {}
      setTheme(next);
    };
    el.addEventListener("click", handler);
    return () => el.removeEventListener("click", handler);
  }, [setTheme]);
  const isDark = mounted && resolvedTheme === "dark";
  return (
    <button
      ref={ref}
      type="button"
      data-kelem-theme-toggle=""
      onClick={() => setTheme(isDark ? "light" : "dark")}
      className={cn(
        buttonVariants({ variant: "outline", size: "icon" }),
        "relative cursor-pointer rounded-[14px] border-border/80 bg-card/60 backdrop-blur-md dark:border-white/10 dark:bg-card/40"
        "inline-flex size-8 shrink-0 cursor-pointer items-center justify-center rounded-[14px] border text-sm font-medium outline-none transition-all",
        "border-border/80 bg-card/60 backdrop-blur-md",
        "hover:bg-muted focus-visible:ring-2 focus-visible:ring-ring",
        "dark:border-white/10 dark:bg-card/40 dark:hover:bg-muted/50"
      )}
      <span className="pointer-events-none inline-flex transition-transform duration-300">
        {!mounted ? (
          <Moon className="size-[1.125rem] opacity-60" aria-hidden />
        ) : isDark ? (
        {isDark ? (
          <Sun className="size-[1.125rem]" aria-hidden />
        {isDark ? (
          <Sun className="size-[1.125rem]" aria-hidden />
          <Sun className="size-4.5" aria-hidden />
        ) : (
          <Moon className="size-[1.125rem]" aria-hidden />
          <Moon className="size-4.5" aria-hidden />
        )}

改动说明：

不再依赖 React 合成事件的 onClick — 改用 useEffect + ref 直接给按钮注册原生 DOM click 事件监听器
直接操作 DOM — 在原生事件处理器中直接 classList.remove/add 切换 light/dark 类，同时写入 localStorage，并同步调用 setTheme 让 next-themes 保持状态一致
去掉了 buttonVariants 依赖 — 改用纯 Tailwind 类名，避免 shadcn Button 组件引入的任何潜在干扰
核心问题在于：在 Next.js 16 + pnpm + App Router 环境下，React 的 hydration 有时不会正确地将合成事件处理器绑定到已有的服务端渲染 DOM 节点上。通过直接使用原生 DOM 事件监听器可以绕开这个问题。
