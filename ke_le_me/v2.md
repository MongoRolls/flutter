# 渴了么 V2 — AI 智能健康助手 实施计划

## 一、目标概述

将「渴了么」从 **"固定目标 + 简单提醒"** 升级为 **"AI 动态预测 + 健康助手 + 长期记忆"** 的智能饮水健康管理 App。

### MVP 功能清单

| # | 功能 | 描述 |
|---|------|------|
| F1 | 自动定位 + 天气获取 | `geolocator` 获取经纬度 → Open-Meteo 获取天气数据，30 分钟缓存 |
| F2 | 动态饮水目标预测 | 规则引擎(体重×天气×运动量)计算建议值，AI 用自然语言解读 |
| F3 | 天气工具 | AI 可在对话中调用 `get_weather` 实时查天气 |
| F4 | 健康助手增强 | system prompt 扩展健康问答能力，支持体检指标文字输入分析 |
| F5 | 结构化长期记忆 | AI 主动提取关键信息（健康、偏好、习惯）→ MemoryFact 永久存储 |
| F6 | 会话摘要 | 返回上一页前自动触发摘要，激活现有死代码 |
| F7 | 自定义提醒 | AI 可帮用户设定提醒（体检、吃药、特定时间喝水等） |
| F8 | Home 页动态目标展示 | 首页展示 AI 推荐值（含天气因子说明），用户可一键采纳 |

### 明确不做

- 拍照/OCR 报告识别
- 后端服务
- 向量检索/RAG
- 系统日历集成
- 数据迁移（全新存储，不动 V1 数据）

### Review 采纳说明

| Review # | 问题 | 采纳方案 |
|----------|------|---------|
| **#1** | SharedPreferences 不适合结构化数据 | V2 新增的 MemoryFact/SessionSummary/CustomReminder 使用 **Hive**；V1 的 KV 数据继续用 SharedPreferences，不做迁移 |
| **#2** | dispose() 时触发摘要不可靠 | 使用 **PopScope** 在导航返回前触发摘要，等完成后再 pop |
| **#3** | dynamicGoalMl 与 dailyGoalMl 关系不清 | `dailyGoalMl` = 用户最终目标（进度/统计/达标全用它）；`dynamicGoalMl` = AI 建议值，仅展示参考；用户可一键采纳但不自动覆盖 |
| **#4** | predict_daily_goal 自动计算和 AI 工具冲突 | `GoalPredictor` 为纯计算服务，`UserProvider` 启动时调用；AI 工具改为只读的 `get_daily_recommendation`，返回已计算好的值 |
| **#5** | System prompt token 爆炸 | MemoryFact 注入上限 20 条（按 importance 降序 + 最近优先）；Summary 上限 3 条；system prompt 总预算 ≤ 1500 tokens；每 category 限 5 条 |
| **#6** | save_health_note 缺用户确认 | 工具执行后 chat UI 显示轻提示 "已记住：XXX"；Settings 新增 "我的健康档案" 入口查看/删除 |
| **#7** | set_reminder 参数缺失 | 明确参数 schema：`title` + `datetime`(ISO 8601) + `repeat`(none/daily/weekly)；不支持复杂循环 |
| **#8** | ChatProvider 将膨胀为 God Class | 拆分为组合模式：`ChatProvider` 协调层 + `tool_handlers/*.dart` + `SystemPromptBuilder` |
| **#9** | Phase 依赖关系有环 | Phase 2 只做 MemoryService CRUD；摘要生成（依赖 AI）移到 Phase 3 末尾 |
| **#10** | WeatherService 缺防护 | 使用 Completer 模式去重并发请求；失败时用过期缓存兜底 |

### 6.2 GoalPredictor 规则引擎（Review #4）

```dart
// lib/core/utils/goal_predictor.dart

class GoalPrediction {
  final int predictedMl;
  final Map<String, double> factors;  // 因子名 → 调整百分比
  final String explanation;           // 人类可读的解释
}

class GoalPredictor {
  /// 纯函数，无副作用
  static GoalPrediction predict({
    required double weightKg,
    required String activityLevel,
    required WeatherData? weather,
  }) {
    double base = weightKg * 35;
    final factors = <String, double>{};

    if (weather != null) {
      // 温度调整
      if (weather.temperature > 35) {
        base *= 1.25; factors['高温(>35°C)'] = 0.25;
      } else if (weather.temperature > 30) {
        base *= 1.15; factors['炎热(>30°C)'] = 0.15;
      } else if (weather.temperature > 25) {
        base *= 1.05; factors['温暖(>25°C)'] = 0.05;
      }

      // 湿度调整
      if (weather.humidity < 30) {
        base *= 1.10; factors['干燥(<30%)'] = 0.10;
      }

      // UV 调整
      if (weather.uvIndexMax > 8) {
        base *= 1.10; factors['强紫外线(UV>8)'] = 0.10;
      } else if (weather.uvIndexMax > 5) {
        base *= 1.05; factors['中等紫外线(UV>5)'] = 0.05;
      }
    }

    // 运动量调整
    switch (activityLevel) {
      case '中等': base *= 1.15; factors['中等运动'] = 0.15;
      case '较多': base *= 1.25; factors['大量运动'] = 0.25;
    }

    final predicted = base.round().clamp(1500, 5000);

    return GoalPrediction(
      predictedMl: predicted,
      factors: factors,
      explanation: _buildExplanation(predicted, factors),
    );
  }
}
```

**调用链**：`UserProvider.loadProfile()` → `GoalPredictor.predict()` → 赋值 `_dynamicGoalMl`

**AI 工具**：`get_daily_recommendation` 为只读，返回 `UserProvider` 中已计算好的值，不重新计算。

### 6.4 WeatherService Completer 去重（Review #10）

```dart
// lib/core/services/weather_service.dart

class WeatherService {
  final Dio _dio;
  WeatherData? _cache;
  Completer<WeatherData>? _pendingRequest;

  Future<WeatherData> getWeather(double lat, double lon) async {
    // 缓存有效 → 直接返回
    if (_cache != null && !_cache!.isExpired) return _cache!;

    // 已有进行中的请求 → 复用
    if (_pendingRequest != null) return _pendingRequest!.future;

    _pendingRequest = Completer();
    try {
      final data = await _fetchFromOpenMeteo(lat, lon);
      _cache = data;
      _pendingRequest!.complete(data);
      return data;
    } catch (e) {
      // 失败时用过期缓存兜底
      if (_cache != null) {
        _pendingRequest!.complete(_cache!);
        return _cache!;
      }
      _pendingRequest!.completeError(e);
      rethrow;
    } finally {
      _pendingRequest = null;
    }
  }
}
```

## 十、风险与降级策略

| 风险 | 降级方案 |
|------|---------|
| 用户拒绝定位权限 | fallback 到默认坐标（北京 39.9/116.4），天气卡片提示 "定位未开启" |
| Open-Meteo 请求失败 | 使用过期缓存数据；无缓存则隐藏天气卡片，dynamicGoalMl = dailyGoalMl |
| DeepSeek API 不稳定 | 现有错误处理已覆盖，不影响新功能 |
| 摘要生成失败（PopScope 中 AI 调用失败） | 静默跳过，不阻塞导航返回 |
| Hive 数据量过大 | MemoryFact 上限 100 条（FIFO），SessionSummary 上限 30 条，过期自动清理 |
| 首次启动无网络 | 跳过天气/定位，全部用默认值，dynamicGoalMl = dailyGoalMl |
| save_health_note 误保存 | system prompt 约束 "发现明确的健康信息时调用"；用户可在健康档案页删除 |
